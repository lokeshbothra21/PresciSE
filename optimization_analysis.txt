# Proposed Optimization Analysis: Chunk Exclusion & Increased Keywords

## Current Behavior Analysis

### Question 1: Does Full Search Re-check Fast Search Chunks?

**Answer: YES, it does re-check them**

**Current Flow**:
```
1. Fast search → Returns 5 chunks (e.g., chunk_1, chunk_2, chunk_3, chunk_4, chunk_5)
2. Full search → Searches ALL chunks (including chunk_1, chunk_2, chunk_3, chunk_4, chunk_5)
3. Merge → Deduplicates using seen_ids set
```

**Code Location**: `core/retrieval/hybrid_retriever.py:147-148`
```python
# PHASE 1: Fast metadata keyword search (~2ms)
fast_results = search_by_keywords(query_str, self.chunks, top_k=5)

# PHASE 2: Full BM25 + FAISS search (existing method)
# ⚠️ THIS SEARCHES ALL CHUNKS, including those in fast_results
full_results = self.retrieve(query_tokens, query_embedding, top_k=top_k)
```

**Why This Happens**:
- `self.retrieve()` operates on `self.chunks` (entire chunk list)
- No mechanism to pass exclusion list to BM25 or FAISS
- Deduplication happens AFTER both searches complete

## Proposed Change 1: Skip Already-Selected Chunks in Full Search

### Implementation Strategy

**Option A: Filter-Based Exclusion** (Recommended)
```python
def retrieve_progressive(self, query_tokens, query_embedding, top_k=15):
    # Phase 1: Fast search
    fast_results = search_by_keywords(query_str, self.chunks, top_k=5)
    
    # Extract fast chunk IDs
    fast_chunk_ids = {item["chunk"]["chunk_id"] for item in fast_results}
    
    # Phase 2: Filter chunks for full search
    filtered_chunks = [c for c in self.chunks if c["chunk_id"] not in fast_chunk_ids]
    
    # Create temporary retriever with filtered chunks
    temp_bm25 = BM25Retriever(filtered_chunks)
    temp_faiss = FAISSRetriever(filtered_chunks)
    
    # Search only unflagged chunks
    bm25_results = temp_bm25.retrieve(query_tokens, top_k=15)
    faiss_results = temp_faiss.retrieve(query_embedding, top_k=15)
    
    # Combine scores (same hybrid logic)
    full_results = self._combine_scores(bm25_results, faiss_results)
    
    # Merge (no duplicates since we excluded them)
    merged = fast_results + full_results
    merged.sort(key=lambda x: x["score"], reverse=True)
    
    return merged[:top_k]
```

**Option B: In-Place Flagging** (More Complex)
```python
# Add flag to chunk objects
for chunk in self.chunks:
    chunk["_temp_selected"] = False

# Fast search marks chunks
for item in fast_results:
    item["chunk"]["_temp_selected"] = True

# Full search skips flagged chunks
unflagged_chunks = [c for c in self.chunks if not c.get("_temp_selected", False)]

# Reset flags after search
for chunk in self.chunks:
    chunk.pop("_temp_selected", None)
```

### Performance Impact: Chunk Exclusion

#### Current Performance (WITH Re-checking):
| Operation | Time | Chunks Searched |
|-----------|------|-----------------|
| Fast search | 2ms | 516 chunks |
| BM25 search | 30ms | **516 chunks** |
| FAISS search | 20ms | **516 chunks** |
| Merge & deduplicate | 1ms | ~20 results |
| **Total** | **53ms** | 516 + 516 + 516 = 1548 chunk operations |

#### Proposed Performance (WITHOUT Re-checking):
| Operation | Time | Chunks Searched |
|-----------|------|-----------------|
| Fast search | 2ms | 516 chunks |
| Filter chunks | **0.1ms** | Create filtered list |
| BM25 search | **28ms** | **511 chunks** (516 - 5) |
| FAISS search | **19ms** | **511 chunks** (516 - 5) |
| Merge (no dedup) | **0.5ms** | Direct concatenation |
| **Total** | **49.6ms** | 516 + 511 + 511 = 1538 chunk operations |

**Speedup**: **53ms → 49.6ms = ~6% faster** (~3.4ms saved)

#### Why Such Small Speedup?

**1. Small Percentage Excluded**:
- Fast search: 5 chunks
- Total corpus: 516 chunks
- Excluded: 5/516 = **0.97%**
- BM25 still searches 99% of chunks
- FAISS still searches 99% of chunks

**2. Overhead of Filtering**:
- Creating filtered list: ~0.1ms
- Memory allocation: minimal
- Lost deduplication savings: ~0.5ms

**3. Computational Cost Distribution**:
```
BM25 cost = O(num_chunks × avg_tokens_per_chunk)
FAISS cost = O(num_chunks × embedding_dim)

Removing 5/516 chunks:
  BM25 savings: 30ms × (5/516) = ~0.29ms
  FAISS savings: 20ms × (5/516) = ~0.19ms
  Total savings: ~0.48ms
```

## Recommendation

### Change 1: Skip Fast-Selected Chunks

**Verdict**: ❌ **NOT RECOMMENDED**

**Why?**:
1. **Minimal speedup**: Only 3.4ms saved (~6%)
2. **Small corpus**: Only 5/516 chunks excluded (0.97%)
3. **Added complexity**: Temporary retriever creation, filtering logic
4. **Current deduplication works fine**: Negligible overhead

**Better approach**: Keep current simple deduplication. The 1ms dedup cost is cheaper than 0.1ms filtering + managing temporary objects.

**When it WOULD make sense**:
- Large corpus (10,000+ chunks)
- Many fast results (50+ chunks)
- Speedup would be: 50/10000 × 50ms = 0.25ms... still tiny!

### Change 2: Increase Keywords to 10 (or 7)

```python
# In core/nlp/metadata_extractor.py

def generate_chunk_metadata(text: str, max_keywords: int = 10) -> Dict[str, Any]:
    """
    Generate keyword metadata for a chunk.
    
    Args:
        text: Chunk text
        max_keywords: Maximum total keywords (default: 10, was 5)
    """
    tfidf_kw = extract_tfidf_keywords(text, top_n=max_keywords)
    ner_kw = extract_entities_spacy(text, top_n=max_keywords)
    
    all_keywords = tfidf_kw + ner_kw
    unique_keywords = []
    seen = set()
    
    for kw in all_keywords:
        kw_lower = kw.lower()
        if kw_lower not in seen:
            unique_keywords.append(kw)
            seen.add(kw_lower)
    
    return {
        "keywords": unique_keywords[:max_keywords]
    }
```

**Complexity**: 1-line change (parameter default)
